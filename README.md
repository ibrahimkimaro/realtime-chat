# Phoenix Realtime Chat & WebRTC Engine 🚀

A high-performance, modular, and resilient realtime communication microservice built with **Elixir**, **Phoenix Framework 1.7**, and **Bandit**.

Designed to be **completely decoupled** from any monolithic application: plug this engine into **any web, mobile, or backend architecture** (React, Next.js, Vue, Flutter, iOS, Android, Python FastAPI, Node.js, Go, etc.) to immediately get instant messaging, typing indicators, read receipts, and WebRTC voice/video calls.

---

## ✨ Features

- **⚡ Blazing Fast & Scalable:** Powered by Erlang/BEAM VM and Bandit HTTP/WebSocket server, capable of handling millions of concurrent connections with negligible memory usage.
- **💬 1-on-1 Direct Messaging:** Private, encrypted-at-rest chat channels with automatic unread tracking and instant delivery.
- **👥 Group Chat Rooms:** Slug-based group channels (`room:<slug>`) with membership and role validation.
- **📞 WebRTC 1-on-1 Voice & Video Calling:** Complete signaling state machine (`call:<id>`), automatic ICE candidate relay, and dynamic time-limited TURN/STUN credential provisioning.
- **🟢 Phoenix Presence:** Real-time online/offline presence tracking across all tabs and devices.
- **✍️ Typing Indicators & Read Receipts:** Instant ephemeral broadcast of typing states (`typing`) and read timestamps (`read_at`).
- **🔔 Backend Webhook Push Dispatch:** Secure internal HTTP endpoints (`POST /internal/events`) to notify users across devices when backend events occur.
- **🛡️ Secure Token Authentication:** Uses lightweight, stateless HMAC-SHA256 tokens (`GET /chat/token`). No database lookups required on WebSocket connect.
- **💾 Low Overhead Postgres Storage:** Direct raw SQL execution with `Postgrex` (no heavy ORM) for maximum throughput and concurrent write pooling.

## 🚀 Quick Start (Docker)

The fastest way to run the service with its PostgreSQL database:

```bash
# 1. Clone your repo
git clone https://github.com/ibrahimkimaro/realtime-chat.git
cd phoenix-realtime-chat

# 2. Copy environment file
cp .env.example .env

# 3. Start PostgreSQL and Phoenix Chat Server
docker compose up -d
```

Your service is now running at:
- **WebSocket Endpoint:** `ws://localhost:4000/socket`
- **Health / Router:** `http://localhost:4000`

## 🔑 Authentication (Token Generation)

Clients authenticate by passing a token in the socket query params:
```text
ws://localhost:4000/socket?token=<TOKEN>
```

The token is generated by **your main backend** using a shared `SECRET_KEY` via HMAC-SHA256:

### Python (FastAPI / Django / Flask)
```python
import time, json, base64, hmac, hashlib

def generate_chat_token(user_id: str, username: str, name: str, is_admin: bool, secret_key: str, ttl_seconds: int = 3600) -> str:
    claims = {
        "sub": str(user_id),
        "name": name,
        "username": username,
        "admin": is_admin,
        "exp": int(time.time()) + ttl_seconds
    }
    part = base64.urlsafe_b64encode(json.dumps(claims).encode()).rstrip(b"=").decode()
    sig = hmac.new(secret_key.encode(), f"chat.{part}".encode(), hashlib.sha256).digest()
    sig_b64 = base64.urlsafe_b64encode(sig).rstrip(b"=").decode()
    return f"{part}.{sig_b64}"
```

### Node.js / TypeScript (Express / Nest / Fastify)
```typescript
import crypto from "crypto";

export function generateChatToken(userId: string, username: string, name: string, isAdmin: boolean, secretKey: string, ttlSeconds = 3600): string {
  const claims = {
    sub: userId,
    name,
    username,
    admin: isAdmin,
    exp: Math.floor(Date.now() / 1000) + ttlSeconds,
  };
  const part = Buffer.from(JSON.stringify(claims)).toString("base64url");
  const sig = crypto.createHmac("sha256", secretKey).update(`chat.${part}`).digest("base64url");
  return `${part}.${sig}`;
}
```

## 💻 Frontend Client Integration (React / TypeScript)

Install the standard Phoenix client:
```bash
npm install phoenix
```

### Connecting to User Socket
```typescript
import { Socket } from "phoenix";

const socket = new Socket("ws://localhost:4000/socket", {
  params: { token: userChatToken },
});

socket.connect();
```

### 1-on-1 Direct Messaging Channel
```typescript
// Join DM channel with another user
const dmChannel = socket.channel(`direct:${otherUserId}`);

dmChannel.join()
  .receive("ok", (resp) => console.log("Joined DM:", resp))
  .receive("error", (err) => console.error("Failed to join:", err));

// Send a message
dmChannel.push("send_msg", {
  client_id: crypto.randomUUID(),
  text: "Hello there!",
});

// Receive incoming messages
dmChannel.on("new_msg", (msg) => {
  console.log("New message received:", msg);
});

// Typing indicator
dmChannel.push("typing", {});
dmChannel.on("typing", ({ user_id, name }) => {
  console.log(`${name} is typing...`);
});
```

### WebRTC Call Signaling Channel
```typescript
const callChannel = socket.channel(`call:${callId}`);

callChannel.join().receive("ok", ({ ice_servers, media, caller }) => {
  // ice_servers contains dynamic STUN & TURN credentials!
  setupPeerConnection(ice_servers);
});

// Send offer / answer / ICE candidates
callChannel.push("offer", { sdp: peerConnection.localDescription.sdp });
callChannel.push("ice_candidate", { candidate: iceEvent.candidate });
```

## 📡 Channels Reference

| Channel Topic | Description | Key Events |
| :--- | :--- | :--- |
| `direct:<user_id>` | 1-on-1 direct conversation | `send_msg`, `new_msg`, `typing`, `read_up_to`, `edit_msg`, `delete_msg` |
| `room:<group_slug>` | Group chat room | `send_msg`, `new_msg`, `typing`, `presence_state`, `presence_diff` |
| `call:<call_id>` | WebRTC voice/video call | `ring`, `accept`, `offer`, `answer`, `ice_candidate`, `hangup` |
| `user:<user_id>` | User notification & badges | `group_invite`, `groups_changed`, incoming call notifications |
| `admin:monitor` | Admin live stats (anonymized) | Telemetry, active socket count, message throughput |

## ⚙️ Environment Variables

| Variable | Required | Default | Description |
| :--- | :---: | :---: | :--- |
| `DATABASE_URL` | **Yes** | — | PostgreSQL connection string |

| `PORT` | No | `4000` | Port for Bandit HTTP/WebSocket server |
| `BACKEND_URL` | No | `http://backend:8000` | Main backend URL for offline Web Push dispatch |

| `TURN_HOST` | No | — | Coturn hostname or public IP |
| `TURN_PORT` | No | `3478` | Coturn standard port |
